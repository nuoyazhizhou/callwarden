- **本卡无新增越界 finding**：C-08/C-09 均在 `allowed_paths` 内闭合，运行时可验证（§2.1/§2.2）。
- **`build_context.*` 差集为已知且已文档化**：Python 端 `ADMIN_ONLY_METHODS` 比 Rust 清单多
  `build_context.register/set_active/delete` 三项（Rust 侧无对应 handler）。本卡未删除这三项，
  仅在注释中如实说明该差集来源，并由 `test_constant_contains_all_expected_methods` 固化，
  避免后续误改。若后续裁决为「与 Rust 逐字一致」，属新 scope，需另建承接卡。

  （`req-99be029cf510` / `req-6301af57dfbc` / `req-2485e306a2ae`）**未携带
  `--evidence-path` / `--evidence-hash`**，导致 `task_events` 的 `reported` 行
  evidence 三元组为空。daemon 的 `task.handoff`（`outcome=executor_ready_for_review`）
  在 `task_collab_lifecycle.rs:1344-1377` 强制要求 handoff 的
  `(step_id, evidence_path, evidence_hash)` 与所引 report 行**逐字相等且非空**
  （`text_field` 拒绝空串），因此首次 handoff 被
  `E_HANDOFF_REPORT_PROVENANCE_MISMATCH` 拒绝（未绕过、未伪造）。处理方式：以本冻结
  manifest 对三个 step **重新 report**（新 request id：
  `req-c0809-s0-ev-20260914` / `req-c0809-s1-ev-20260914` / `req-c0809-s2-ev-20260914`），
  再以 step2 的新 report 行发起 handoff。三 step 的 `task_steps.status` 恒为 `done`，
  无代码返工。
- **C-13/C-14/C-15（`rust_ext/**`）不在本卡 scope**：仍按 backlog §W14 登记，保持待建承接卡。
- 未使用任何本地 SQLite 旁路或伪造成果；未触碰 `forbidden_paths`（`db/`、
