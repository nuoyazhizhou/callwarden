### 0.1 根因

**C-14**：`handle_assignment_create` 的 INSERT 列清单**缺 `assignment_id`**，而该列为
`TEXT NOT NULL UNIQUE`（`db/schema.py:1629`）→ 任何调用恒
`NOT NULL constraint failed: task_assignments.assignment_id`；且返回值取
`conn.last_insert_rowid()`（整数），与文档/MCP schema 的 `ASG-<uuid>` 契约不符。

**C-15**：`handle_assignment_revoke` 入参为 `task_id`（+`role`/`reason`），与契约面
（MCP tool schema / `docs/mcp_tools.md:1972` / `docs/cli_reference.md` / CLI
`_METHOD_MAP` / Python `db.revoke_assignment`）**五面一致要求 `assignment_id`** 相悖；
返回体为 `{ok, task_id, role, reason}` 亦与文档 `{ok, assignment_id, revoked_at}` 不符。

**C-17（本卡实测新发现，已卡内收敛修复）**：`admin.assignment_*` 路由经
`owned_workspace` 拿到的 `workspace_id` 是 **daemon registry 代理 id**
（`daemon_workspaces.workspace_id`；本实例实测 `daemon/registry.db`=**36**、
`registry.db`=**207**），而 `task_assignments` 物理落在
`%USERPROFILE%\.callwarden\callwarden.db`，其 `workspaces.id` ∈ {1,2,3,5,6,7,8,9,10,11,17,19,20,21}。
`task_assignments` 带 `FOREIGN KEY (workspace_id) REFERENCES workspaces(id)`（`db/schema.py:1638`）
→ 照搬代理 id 会让 `create` **恒 FK 失败**；`revoke` 的 `WHERE workspace_id=?` 亦恒匹配不到行，
会把合法撤销误报 `assignment_not_found`（C-14 的 NOT NULL 恰好掩盖了该缺陷）。

### 4.2 C-17 的剩余暴露面（同库、其他 handler）

### 4.5 step#3「往返用例」口径说明（诚实披露）

step#3 的「show → create → revoke 往返可用」由 **§2.6 对已部署 daemon 的实跑六步**承担，
未额外新增「隔离 daemon live 往返」pytest，原因如实记录：

- 隔离 daemon 夹具 `tests/convergence/conftest.py:42-48 _pick_bin()` **优先取**
  `rust_ext/target/release/cw-daemon.exe`；本机该文件 LastWriteTime = **13/9/2026 8:19:25**，
  **早于本卡 C-17 修复**（不含修复）→ 直接复用共享夹具会得到**失真失败**（FK 报错），
  属环境陈旧而非源码缺陷；
- 含修复的 release 产物在 `rust_ext/target/stage-refresh/release/cw-daemon.exe`
  （14/9/2026 11:40:32，即规则 43 部署门禁的构建输出）；
- 修改共享夹具 `_pick_bin()`（改为「取最新构建」）会改变**全套收敛测试**的二进制解析口径，
  属本卡 `executor_allowed` 之外的语义变更、blast radius 不可控 → 本卡不做；
- 故 step#3 采用与 C-13 卡 `tests/test_c13_semgrep_dispatch_wiring.py` **同款**源码契约
  回归（确定性、零环境依赖）固化 NOT NULL 与入参/WHERE/返回体契约；「往返可用」以实跑
  回执（§2.6）+ 部署门禁三方哈希一致（§2.4）为准。
