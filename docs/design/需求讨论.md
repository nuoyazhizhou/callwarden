## 设计方案：task_discussions 表

新增一张表承载多 agent 之间的异步对话：

```sql
CREATE TABLE IF NOT EXISTS task_discussions (
    id TEXT PRIMARY KEY,              -- msg_xxx
    task_id TEXT NOT NULL,
    step_id TEXT DEFAULT '',           -- 挂到具体 step（可选）
    parent_msg_id TEXT DEFAULT '',     -- 回复某条消息（支持 thread）
    author TEXT NOT NULL,              -- 'trae' / 'qoder' / 'opencode' / 'reviewer' / 'tester'
    role TEXT NOT NULL DEFAULT 'comment',  -- design / review / implement / test / comment / block / approve
    status TEXT NOT NULL DEFAULT 'open',   -- open / addressed / resolved / wontfix
    content TEXT NOT NULL,            -- 消息正文（markdown）
    evidence TEXT DEFAULT '',          -- 证据 JSON（符号 hash / diff / 测试日志摘要）
    severity TEXT DEFAULT 'info',      -- info / warn / error / block（仅 review/test 角色有意义）
    created_at REAL NOT NULL,
    resolved_at REAL,
    resolved_by TEXT DEFAULT '',
    FOREIGN KEY (task_id) REFERENCES tasks(id)
);
CREATE INDEX IF NOT EXISTS idx_discussions_task ON task_discussions(task_id);
CREATE INDEX IF NOT EXISTS idx_discussions_status ON task_discussions(status);
CREATE INDEX IF NOT EXISTS idx_discussions_parent ON task_discussions(parent_msg_id);
```

## 关键设计决策

1. **异步非阻塞**：agent 发完消息立即返回，不等回复。其他 agent 轮询 `discussion_list` 或用 `cw discussion wait --task <id> --since <ts>` 阻塞等待新消息。

2. **severity + status 双维度**：
   - `severity=block` + `status=open` → 阻止 task_close
   - `severity=error` + `status=open` → 警告但不阻止
   - `status=resolved` → 已解决，不阻止

3. **thread 支持**：`parent_msg_id` 允许回复形成讨论树，避免扁平列表难以跟踪。

4. **证据链**：`evidence` 字段挂载符号 hash、diff、测试日志，让反馈可追溯。

5. **角色驱动**：`role` 字段让消息来源清晰，agent 可以只看 `role=review` 的消息。

### 第 2 层：基于符号调用链自动推断

```python
def infer_task_dependencies(self, new_task_id: str, target_symbols: List[str]):
    """基于调用链自动推断 task 依赖
    
    分析 new_task 要改的符号调用了哪些其他符号，
    如果被调用符号属于另一个 open/in_progress 的 task，自动建立依赖。
    """
    for sym_qname in target_symbols:
        callees = self.get_callees(sym_qname)
        for callee in callees:
            # 查找 callee 符号所属的文件/符号是否属于某个 task
            callee_task = self._find_task_by_symbol(callee["qualified_name"])
            if callee_task and callee_task["id"] != new_task_id:
                # 自动建立依赖：new_task 依赖 callee_task
                self._add_task_dependency(
                    new_task_id, callee_task["id"],
                    dependency_type="inferred_callchain"
                )
```

**场景**：
- Task B（UserService）的 `login()` 方法调用 `UserMapper.findByUsername()`
- cw 发现 `UserMapper.findByUsername` 属于 Task A
- 自动建立：Task B depends_on Task A

1. 先过滤 `status != 'closed'` 的任务
2. 再过滤 `depends_on` 所有前置任务已 `closed` 的任务

```python
def task_next_step(self):
    """返回下一个可执行的任务 step（依赖满足 + 底层优先）"""
    # 1. 找所有未完成的 task
    # 2. 过滤掉被阻塞的（有未 closed 的 depends_on）
    unblocked = [t for t in tasks if self._is_unblocked(t["id"])]
    # 3. 按 layer 排序（mapper < service < controller）
    unblocked.sort(key=lambda t: (self._get_layer_order(t["layer"]), t["sort_order"]))
    # 4. 返回第一个
    return unblocked[0] if unblocked else None
```

**gate_type 区分**：
- `hard`：前置必须 `closed`（需求→设计→实现，硬阻塞）
- `soft`：前置 `review` 即可（设计评审通过就能开始实现，不必等 closed）

### task_next_step 改造

```python
def task_next_step(self, agent_id: str = "") -> Optional[Dict]:
    """返回下一个可执行的任务 step
    
    门禁检查：
    - hard 依赖：前置任务必须 status='closed'
    - soft 依赖：前置任务必须 status in ('review', 'applied', 'closed')
    - 无依赖或依赖满足：可领取
    """
    ws_id = self._get_active_workspace_id()
    
    # 查找所有 pending step（所属 task 未完成）
    cur = self.conn.execute("""
        SELECT ts.*, t.title, t.status as task_status
        FROM task_steps ts
        JOIN tasks t ON ts.task_id = t.id
        WHERE t.workspace_id IS NULL OR t.workspace_id = ?
          AND ts.status = 'pending'
        ORDER BY ts.created_at ASC
    """, (ws_id,))
    
    for step in cur:
        task_id = step["task_id"]
        if self._is_task_gated(task_id):
            continue  # 被门禁阻塞，跳过
        
        # 门禁通过 → 领取
        return self._claim_step(step)
    
    return None  # 所有任务都被门禁阻塞

def _is_task_gated(self, task_id: str) -> bool:
    """检查任务是否被门禁阻塞"""
    cur = self.conn.execute("""
        SELECT td.gate_type, t.status as dep_status
        FROM task_dependencies td
        JOIN tasks t ON td.depends_on_task_id = t.id
        WHERE td.task_id = ?
    """, (task_id,))
    
    for row in cur:
        if row["gate_type"] == "hard":
            if row["dep_status"] != "closed":
                return True  # 硬门禁：前置未 closed → 阻塞
        elif row["gate_type"] == "soft":
            if row["dep_status"] not in ("review", "applied", "closed"):
                return True  # 软门禁：前置未到 review → 阻塞
    
    return False  # 所有依赖满足，不阻塞
```

```python
                    )
    
    return task_id
```

### claim 机制

```python
def task_claim(self, task_id: str, agent_id: str, 
               lease_ttl: int = 1800) -> Optional[Dict]:
    """agent 主动领取任务 step（原子操作）
    
    流程：
    1. 先释放自己过期的租约（防止上次崩溃残留）
    2. 找到第一个可领取的 step（pending 或租约过期的 in_progress）
    3. 检查门禁依赖 + 作用域冲突
    4. 原子 UPDATE：claimed_by=agent_id, status=in_progress, lease_expires_at=now+ttl
    5. 返回 step 详情
    
    Args:
        task_id: 任务 ID
        agent_id: 领取的 agent 标识（如 "trae-session-abc123"）
        lease_ttl: 租约时长（秒），默认 30 分钟
    """
    now = time.time()
    
    # 1. 释放自己过期的租约（上次崩溃残留）
    self._release_expired_leases(agent_id=agent_id, only_own=True)
    
    # 2. 找到可领取的 step
    step = self._find_claimable_step(task_id, now)
    if not step:
        return None
    
    # 3. 门禁 + 作用域检查
    if self._is_task_gated(step["task_id"]):
        return None  # 被门禁阻塞
    if self._has_scope_conflict(step["task_id"]):
        return None  # 作用域冲突
    
    # 4. 原子领取（防止并发竞争）
    cur = self.conn.execute("""
        UPDATE task_steps 
        SET status = ?, claimed_by = ?, claimed_at = ?, 
            lease_expires_at = ?, last_heartbeat_at = ?
        WHERE id = ? AND status IN (?, ?)
          AND (lease_expires_at < ? OR lease_expires_at = 0)
    """, (STEP_STATUS_IN_PROGRESS, agent_id, now, 
          now + lease_ttl, now,
          step["step_id"],
          STEP_STATUS_PENDING, STEP_STATUS_IN_PROGRESS,
          now))
    
    if cur.rowcount == 0:
        # 被其他 agent 抢走了
        return None
    
    return self._format_step_detail(step, agent_id, now + lease_ttl)
```

### resume 机制

```python
def task_resume(self, agent_id: str) -> Optional[Dict]:
    """agent 重新进入时，查找自己未完成的 step
    
    场景：agent 被杀死 / 额度用完 / 重启后重新进入
    
    流程：
    1. 查找 claimed_by=agent_id 且 status=in_progress 的 step
    2. 如果租约未过期 → 直接返回（续做）
    3. 如果租约已过期 → 重新领取（续租）
    """
    now = time.time()
    
    cur = self.conn.execute("""
        SELECT * FROM task_steps
        WHERE claimed_by = ? AND status = ?
        ORDER BY claimed_at DESC
        LIMIT 1
    """, (agent_id, STEP_STATUS_IN_PROGRESS))
    step = cur.fetchone()
    
    if not step:
        # 没有未完成的 step → 领新任务
        return None
    
    if step["lease_expires_at"] > now:
        # 租约未过期 → 继续做
        return self._format_step_detail(step, agent_id, step["lease_expires_at"])
    
    # 租约已过期 → 重新领取（续租）
    new_lease = now + DEFAULT_LEASE_TTL_SEC
    self.conn.execute("""
        UPDATE task_steps
        SET lease_expires_at = ?, last_heartbeat_at = ?
        WHERE id = ? AND claimed_by = ?
    """, (new_lease, now, step["id"], agent_id))
    
    return self._format_step_detail(step, agent_id, new_lease)


def task_find_my_work(self, agent_id: str) -> List[Dict]:
    """查找 agent 所有未完成的 step（可能跨多个任务）
    
    场景：agent 重启后想知道"我之前在干什么"
    """
    cur = self.conn.execute("""
        SELECT ts.*, t.title as task_title
        FROM task_steps ts
        JOIN tasks t ON ts.task_id = t.id
        WHERE ts.claimed_by = ? AND ts.status = ?
        ORDER BY ts.claimed_at DESC
    """, (agent_id, STEP_STATUS_IN_PROGRESS))
    return [dict(row) for row in cur]
```

### 心跳续租

```python
def task_heartbeat(self, step_id: str, agent_id: str, 
                    extend_by: int = 1800) -> Dict:
    """agent 定期续租（心跳）
    
    场景：agent 还在干活，但需要延长租约
    
    失败情况：
    - step 不属于这个 agent → 拒绝（租约已被抢）
    - step 已 completed/blocked → 无需续租
    """
    now = time.time()
    cur = self.conn.execute("""
        UPDATE task_steps
        SET last_heartbeat_at = ?, lease_expires_at = ?
        WHERE id = ? AND claimed_by = ? AND status = ?
    """, (now, now + extend_by, step_id, agent_id, STEP_STATUS_IN_PROGRESS))
    
    if cur.rowcount == 0:
        return {"ok": False, "reason": "step 不属于此 agent 或已结束"}
    return {"ok": True, "lease_expires_at": now + extend_by}
```

### 自动释放过期租约

```python
def _release_expired_leases(self, agent_id: str = None, only_own: bool = False):
    """释放过期的租约（step 回到 pending）
    
    场景：
    - agent 被杀死、额度用完、崩溃
    - 租约过期后 step 自动回 pending，其他 agent 可领
    
    Args:
        agent_id: 只释放此 agent 的过期租约（None=所有）
        only_own: 仅释放指定 agent 的（不影响其他 agent）
    """
    now = time.time()
    
    if agent_id and only_own:
        # 只释放自己的过期租约（claim 前清理）
        self.conn.execute("""
            UPDATE task_steps
            SET status = ?, claimed_by = '', 
                lease_expires_at = 0, last_heartbeat_at = 0
            WHERE claimed_by = ? AND status = ? AND lease_expires_at < ?
        """, (STEP_STATUS_PENDING, agent_id, 
              STEP_STATUS_IN_PROGRESS, now))
    else:
        # 释放所有过期租约（定期清理任务）
        self.conn.execute("""
            UPDATE task_steps
            SET status = ?, claimed_by = '',
                lease_expires_at = 0, last_heartbeat_at = 0,
```

## 与门禁/作用域协同

```python
def _find_claimable_step(self, task_id: str, now: float) -> Optional[Dict]:
    """找到可领取的 step（门禁满足 + 作用域无冲突 + pending/过期）"""
    
    # 1. 释放所有过期租约
    self._release_expired_leases()
    
    # 2. 找 pending step（按门禁 + 作用域过滤）
    cur = self.conn.execute("""
        SELECT ts.*, t.title as task_title, t.status as task_status
        FROM task_steps ts
        JOIN tasks t ON ts.task_id = t.id
        WHERE ts.status = ?
          AND (ts.claimed_by = '' OR ts.claimed_by IS NULL)
        ORDER BY ts.created_at ASC
    """, (STEP_STATUS_PENDING,))
    
    for step in cur:
        # 门禁检查
        if self._is_task_gated(step["task_id"]):
            continue
        # 作用域冲突检查
        if self._has_scope_conflict(step["task_id"]):
            continue
        return step
    
    return None
```

## 关键设计决策

1. **claim 是原子操作**：`UPDATE ... WHERE status IN (pending, in_progress) AND lease_expires_at < now`，防止并发竞争。

2. **租约时长可配置**：默认 30 分钟，长任务可 `--lease-ttl 7200`（2 小时）。

3. **被动清理优先**：不需要后台进程，每次 claim 时清理过期租约。

4. **agent_id 持久化**：写入 `claimed_by` 字段，agent 重启后能找到自己的 step。

5. **心跳可选**：不强制心跳，靠租约过期自动释放。心跳只是延长租约的手段。

## 契约的本质

```
task description = 自然语言，LLM 可幻觉
契约 = 结构化 + 可验证，LLM 不能造假

例如 "UserService.login 依赖 UserMapper.findByUsername"
  - description 写法：LLM 可能编造接口名
  - 契约写法：cw 查 symbol 表验证，编造就报错
```

## 当前 cw 已有的契约能力

我们 P0-P6 迁移过程中引入的契约：

| 契约类型             | 用途               | 工具                         |
| -------------------- | ------------------ | ---------------------------- |
| `rollback_config`    | Rust 短路回滚门禁  | `is_feature_rolled_back()`   |
| `migration-manifest` | Phase 迁移状态门禁 | migration-manifest.md        |
| Rust-Python 契约     | 跨语言调用边界     | `docs/design/*-contract.md`  |
| Before-Edit Contract | 编辑前安全检查     | `guardrail_check_edit`       |
| Symbol 契约          | 符号签名验证       | `get_symbol` + `symbol_hash` |

这些全是**机器可验证**的——LLM 不能伪造一个不存在的符号、不能绕过 rollback 标志。

## task 内嵌契约的设计

每个 task 应该携带**三个层次的契约**：

### Layer 1：依赖契约（门禁）

```python
# task 创建时声明依赖符号（不是依赖 task）
cw task create --title "实现 UserService" \
  --requires-symbol "UserMapper.findByUsername" \
  --requires-symbol "AuthUtils.hashPassword"
# cw 验证：这些符号必须存在（已 closed task 的产物或已有代码）
# 不存在 → 拒绝创建 task，提示先完成依赖任务
```

### Layer 2：作用域契约（边界）

```python
cw task create --title "实现 UserService" \
  --target-symbol "UserService.login" \
  --target-symbol "UserService.logout" \
  --target-file "src/service/UserService.java"
# task 只能修改这些符号/文件，guardrail_check_edit 强制
```

### Layer 3：验收契约（门禁）

```python
cw task create --title "实现 UserService" \
  --acceptance "symbol:UserService.login" \
  --acceptance "symbol:UserService.logout" \
  --acceptance "callers:UserService.login" \  # 必须有调用方
  --acceptance "test:test_login_success"      # 必须有测试
# task_close 时 cw 验证所有 acceptance 契约
```

## 为什么契约能解决幻觉

```
单 IDE 场景：
  Trae 设计 → "UserService.login 调用 UserMapper.findUserByName"
  ↓ 上下文污染
  Implement subagent → 用 findUserByName（幻觉，实际是 findByUsername）
  ↓
  Test subagent → 测 findUserByName（测的都是幻觉的接口）
  ↓
  Review subagent → 检查 findUserByName（同上下文，发现不了）

多 IDE + 契约场景：
  Trae → 契约: requires-symbol "UserMapper.findByUsername"
  ↓
  Qoder 独立设计 → 写 UserService.login
  ↓ task_close 时 cw 验证：

    → close 失败，Qoder 必须修正
  ↓
  OpenCode → 独立实现 Controller，调用 UserService.login
  ↓ cw 验证 symbol 存在 + hash 匹配
```

**契约就是 LLM 间的事实校验层**。

## Schema 改动（最小）

```sql
-- 1. task_acceptance：验收契约（task_close 时验证）
CREATE TABLE IF NOT EXISTS task_acceptance (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    task_id TEXT NOT NULL,
    contract_type TEXT NOT NULL,       -- symbol / callers / test / file_exists / custom
    contract_value TEXT NOT NULL,      -- 符号全名 / 测试名 / 文件路径
    operator TEXT DEFAULT 'exists',     -- exists / callers_gte_1 / test_pass / hash_eq
    expected_value TEXT DEFAULT '',     -- 期望值（如 hash）
    verified INTEGER DEFAULT 0,         -- 0=未验证 1=已通过
    verified_at REAL,
    FOREIGN KEY (task_id) REFERENCES tasks(id)
);
CREATE INDEX IF NOT EXISTS idx_acceptance_task ON task_acceptance(task_id);

-- 2. task_dependencies：依赖契约（requires-symbol 隐式建立）
CREATE TABLE IF NOT EXISTS task_dependencies (
    task_id TEXT NOT NULL,
    depends_on_task_id TEXT NOT NULL,
    dependency_type TEXT DEFAULT 'hard',  -- hard=必须closed / soft=review即可
    inferred_from TEXT DEFAULT '',         -- 'requires-symbol:UserMapper.findByUsername'
    PRIMARY KEY (task_id, depends_on_task_id),
    FOREIGN KEY (task_id) ACCEPT_REFERENCES(tasks(id))
);
CREATE INDEX IF NOT EXISTS idx_task_deps ON task_dependencies(depends_on_task_id);

-- 3. task_steps 加 2 字段（租约）
ALTER TABLE task_steps ADD COLUMN claimed_by TEXT DEFAULT '';
ALTER TABLE task_steps ADD COLUMN claimed_at REAL DEFAULT 0;
```

## task_close 契约验证

```python
def task_close(self, task_id: str) -> Dict:
    """关闭任务前验证所有 acceptance 契约"""
    # 1. 查询所有未验证的 acceptance
    cur = self.conn.execute(
        "SELECT * FROM task_acceptance WHERE task_id=? AND verified=0",
        (task_id,)
    )
    contracts = cur.fetchall()
    
    # 2. 逐个验证
    for c in contracts:
        result = self._verify_contract(c)
        if not result["ok"]:
            return {
                "ok": False,
                "reason": f"契约未满足: {c['contract_type']} {c['contract_value']}",
                "detail": result["detail"]
            }
        # 标记已验证
        self.conn.execute(
            "UPDATE task_acceptance SET verified=1, verified_at=? WHERE id=?",
            (time.time(), c["id"])
        )
    
    # 3. 所有契约通过 → close
    self._do_task_close(task_id)
    return {"ok": True}
```

## 3. db/db_guardrail.py 的 check_before_edit 方法签名和用途

**方法签名与实现**：

```python
def check_before_edit(self, file_path: str, proposed_change: str = "") -> Dict:
    """编辑前阻断式检查

    Args:
        file_path: 文件路径（相对路径或绝对路径）
        proposed_change: 拟议的修改内容（可选，为空则读取磁盘上的当前内容）

    Returns:
        {"decision": "block"/"warn"/"pass", "findings": [...], "message": "..."}
        若存在 block 级别 finding，decision 为 block
    """
```

**用途与执行流程**：
1. 路径规范化（`\\` → `/`）
2. 获取待检查内容：若 `proposed_change` 非空则直接用，否则从磁盘读取当前内容（`_load_file_content_for_check`）
3. 运行三类检测器（不持久化，仅返回结果）：
   - `_detect_db_safety`（数据库安全）
   - `_detect_api_compat`（API 兼容性）
   - `_detect_incident_readiness`（事故就绪）
4. 为每个 finding 补充 `file_path` 字段
5. 判定决策：`block > warn > pass`
   - 有 block 级 finding → `decision="block"`（编辑不允许）
   - 仅 warn 级 finding → `decision="warn"`（编辑前审查）
   - 无 finding → `decision="pass"`（编辑允许）

**表间关系说明**：
- `tasks` 与 `task_steps` 通过 `task_id` 一对多关联（外键约束）

## 设计文档核心要点
