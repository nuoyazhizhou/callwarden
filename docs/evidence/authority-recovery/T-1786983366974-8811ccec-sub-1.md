## Implementation

`handle_lease_acquire` now checks an unexpired active lease holder's
`agent_registrations` row inside the same SQLite transaction. A missing,
inactive, or heartbeat-stale holder is treated as an orphan; the old lease is
marked `expired`, an append-only `expire` lease event is written with the old
fencing counter and recovery actor, and only then is the replacement lease
created. A fresh active heartbeat still returns `E_LEASE_ACTIVE_EXISTS`.

The recovery path is serialized by the existing daemon connection mutex and
does not write `task_events`, `task_steps`, evidence, or verdict history.
